# ICMP, ping, tracert и Wireshark

## Пакеты
Люди общаются словами, компьютеры — пакетами.
У каждого пакета есть адрес отправителя и получателя, как у письма в конверте.

## ping
Проверка связи с хостом (любым устройством в сети).
Отправляет пакет «ты тут?» и ждёт ответа «я тут».

## TTL (Time To Live)
Сколько роутеров ещё может пройти пакет.
Каждый роутер уменьшает TTL на 1, при 0 пакет выбрасывается.
Начальные значения: Windows — 128, Linux — 64.

Мой пример: `ping 8.8.8.8` → TTL=117 → 128 − 117 = 11 роутеров.

## tracert
Показывает все роутеры на пути до цели. Работает через TTL = 1, 2, 3...

Мой пример: `tracert 8.8.8.8` → 11 роутеров + сама цель = 12 строк.
Совпало с расчётом по TTL.

## Wireshark
Анализатор трафика: захватывает пакеты, проходящие через сетевую карту,
позволяет отфильтровать нужные и раскрыть содержимое каждого.

### Как поймать свой ping
1. Запустить захват
2. Выполнить `ping 8.8.8.8` в cmd
3. Остановить захват
4. Фильтр `icmp` → 8 строк: 4 запроса и 4 ответа

### Что внутри пакета («конверты»)
- **Ethernet II** — внешний конверт: доставка до следующего устройства в локальной сети по MAC-адресам
- **Internet Protocol Version 4** — конверт с IP-адресами: доставка через интернет до конечной цели
- **ICMP** — само письмо: «ты тут?» / «я тут»

### Запрос (Echo request)
```
Ethernet II, Src: 60:cf:84:84:5a:4b (мой ПК), Dst: 08:bf:b8:96:36:20 (роутер)
Internet Protocol Version 4
    Time to Live: 128                ← пакет только начал путь
    Protocol: ICMP (1)
    Source Address: 192.168.50.207   ← отправитель (я)
    Destination Address: 8.8.8.8     ← получатель (Google)
```

### Ответ (Echo reply)
```
Ethernet II, Src: 08:bf:b8:96:36:20 (роутер), Dst: 60:cf:84:84:5a:4b (мой ПК)
Internet Protocol Version 4
    Time to Live: 117                ← осталось после пути: 128 − 117 = 11 роутеров
    Protocol: ICMP (1)
    Source Address: 8.8.8.8          ← отправитель (Google)
    Destination Address: 192.168.50.207  ← получатель (я)
```

### Выводы
- В ответе Source и Destination поменялись местами: ответ — это новое письмо от Google ко мне.
- MAC-получатель моего запроса — роутер, а не Google: MAC работает только внутри локальной сети.
  IP-адрес — конечная цель, MAC-адрес — следующий шаг.
- В простое большая часть трафика — служебные локальные протоколы (ARP, STP, SSDP, mDNS),
  а интернет-трафик почти весь зашифрован (TLS).
